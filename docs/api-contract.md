# API-контракт order-service, версия 1

Дата фиксации: 18.11.2026. HTTP JSON, UTF-8; время UTC ISO 8601.

| Метод | Путь | Назначение | Коды |
|---|---|---|---|
| POST | /orders | Проверить пользователя по HTTP и создать заказ | 201, 400, 404, 503 |
| GET | /orders | Список заказов | 200 |
| GET | /orders/{order_id} | Получить заказ | 200, 400, 404 |
| GET | /health | Локальная живость, БД и состояние breaker | 200 |

POST: {"user_id":1,"total":1500.50}. Положительный целый user_id, числовой total >0, до 1 млрд, максимум 2 знака после запятой. Лишние поля и неверный JSON → 400. Ответ: {"id":42,"user_id":1,"total":1500.5,"status":"created","created_at":"2026-11-18T10:00:00Z"}. Пользователь проверяется до записи заказа. 404 пользователя не повторяется; при недоступности зависимости заказ не создаётся, возвращается 503. Ошибка: {"error":"описание"}.

HTTP-клиент: таймаут 2 с на попытку, всего 3 попытки GET; задержки между ними 0,5 и 1 с (после последней попытки задержки нет). Circuit breaker: 5 неуспешных логических запросов → OPEN на 30 с; затем одна HALF_OPEN-проба. Успех/404 закрывает breaker. POST заказа автоматически не повторяется. /health проверяет локальный процесс и БД, а не доступность user-service: иначе отказ зависимости приводил бы к каскадной потере готовности.

После сохранения заказа событие OrderCreated сохраняется транзакционно в outbox, затем публикуется в durable RabbitMQ очередь order_created с publisher confirms. Notification-service фиксирует event_id для идемпотентности и ACK после сохранения уведомления. Повторная доставка допустима, потеря после подтверждённого сохранения предотвращается outbox.

OpenAPI: /openapi.json; Swagger: /docs. /metrics/ — экспорт Prometheus. Gateway: /api/orders, /docs/orders/docs.
